# MyRTOS C 版总体设计草案

> 状态：已获用户批准，可进入实现计划阶段。  
> 范围：用户已选择 C，即“大而全”的类 FreeRTOS 嵌入式 RTOS 路线。  
> 原则：参考 FreeRTOS 的公开架构思想，不复制 FreeRTOS 源码、注释、手册原文或受保护表达。

## 1. 目标

MyRTOS 是一个原创的轻量级嵌入式实时操作系统，面向 STM32 与 DSP 平台，提供任务调度、同步通信、软件定时、内存管理、低功耗、跟踪诊断和可移植端口层。最终交付物包含：

- 可编译的 C99/C11 内核源码。
- STM32 Cortex-M4/M7 ARM GCC/CMake 移植层。
- TI C2000 风格 DSP 抽象移植层。
- 完整 host 侧单元测试、调度仿真测试、模块耦合测试。
- 嵌入式端口 smoke test 示例。
- 专业中文注释：每个函数说明功能、参数、返回值、调用示例，并对函数内部关键步骤逐行注释。
- 原创中文使用手册：结构接近官方 RTOS 参考手册的“章节化 API + 参数 + 返回值 + 示例 + 注意事项”写法，但文本与排版表达保持原创。

## 2. 默认平台假设

因当前未收到更具体硬件型号，先采用以下默认组合推进设计：

- STM32：Cortex-M4/M7，ARM GNU Toolchain，CMake 构建。
- DSP：TI C2000 风格模型，先提供端口抽象与 host/mock 测试；真实汇编上下文切换作为独立端口文件实现。
- Host 测试：Windows 本机可运行的 C 测试工程，用于验证内核算法与模块耦合。

若后续用户指定 STM32F103、STM32F407、STM32H743、C28x、C66x 或其他 DSP，端口层按相同接口替换。

## 3. 架构总览

MyRTOS 分四层：

1. 应用层：用户任务、回调、驱动适配代码。
2. 内核服务层：任务、队列、信号量、互斥锁、事件组、定时器、缓冲、通知、内存管理。
3. 内核基础层：链表、优先级位图、时间片、阻塞超时、临界区抽象、配置宏、断言与 trace。
4. 移植层：CPU 上下文切换、tick 中断、临界区开关、栈初始化、编译器属性、字长/对齐。

数据流：

- ISR 通过 `FromISR` API 唤醒任务。
- 内核对象把等待任务挂入对象等待链表。
- tick 或事件发生后，任务从阻塞链表移动到就绪链表。
- 调度器选择最高优先级就绪任务。
- 移植层完成上下文切换。

## 4. 模块划分

### 4.1 任务与调度

职责：

- 创建、删除、挂起、恢复任务。
- 支持优先级抢占、同优先级时间片、协作式可配置模式。
- 支持阻塞延时、绝对时间延时、无限等待。
- 维护就绪链表、延时链表、挂起链表、删除回收链表。

核心对象：

- `MRT_TaskControlBlock`：任务控制块。
- `MRT_SchedulerState`：调度器全局状态。
- `MRT_List` / `MRT_ListNode`：通用双向链表。

### 4.2 队列

职责：

- 固定长度、固定元素大小 FIFO。
- 支持发送、接收、覆盖、窥视。
- 支持任务上下文与 ISR 上下文 API。
- 作为信号量、互斥锁部分机制的底层构件之一。

边界：

- 队列仅负责数据复制与等待任务管理。
- 优先级继承只归互斥锁模块处理。

### 4.3 信号量与互斥锁

职责：

- 二值信号量：事件通知。
- 计数信号量：资源计数。
- 互斥锁：所有权、递归可选、优先级继承。
- 递归互斥锁：同一任务可重复获取。

耦合重点：

- 互斥锁依赖任务优先级管理。
- ISR 不允许获取互斥锁。
- 优先级继承需在超时、释放、删除任务时回滚。

### 4.4 事件组

职责：

- 多 bit 事件等待。
- 支持 wait-all / wait-any。
- 支持退出时清位。
- 支持 ISR 置位。

耦合重点：

- 多任务等待同一事件组。
- 事件置位后同时唤醒多个任务。
- 与超时链表共同决定返回状态。

### 4.5 任务通知

职责：

- 每任务内建轻量通知槽。
- 支持 set bits、increment、overwrite、no-overwrite。
- 支持等待、清位、取值。

设计选择：

- 默认支持 1 个通知槽。
- 可通过配置扩展为多个通知槽。

### 4.6 软件定时器

职责：

- 单次定时器。
- 周期定时器。
- 启动、停止、复位、修改周期。
- 定时器服务任务执行回调。

耦合重点：

- 定时器命令队列耦合队列模块。
- 定时器服务任务耦合任务调度。
- 回调不允许调用可能长时间阻塞的 API。

### 4.7 流缓冲与消息缓冲

职责：

- 流缓冲：字节流，适合 UART/SPI 数据。
- 消息缓冲：带长度帧，保持消息边界。
- 支持任务与 ISR API。

耦合重点：

- 发送阻塞与接收阻塞不能同时破坏环形缓冲一致性。
- ISR 写入后按需触发上下文切换。

### 4.8 内存管理

职责：

- 静态对象创建。
- 固定块池。
- 简单线性堆。
- 可释放堆。
- 合并空闲块堆。

安全策略：

- 内核公共 API 优先支持静态创建。
- 动态创建由配置开关启用。
- 所有分配失败路径必须可测试。

### 4.9 Tickless Idle

职责：

- 计算可睡眠 tick 数。
- 进入低功耗前暂停 tick。
- 唤醒后校正系统 tick。

端口要求：

- STM32 端口提供 SysTick 或低功耗定时器钩子。
- DSP 端口提供定时器停止/恢复钩子。

### 4.10 Trace、统计与断言

职责：

- trace hook：任务切换、队列发送、队列接收、阻塞、唤醒、定时器回调。
- 运行时间统计：任务运行计数。
- 断言：配置错误、非法上下文、空指针、对象状态错误。

设计选择：

- trace 默认空实现。
- 用户可通过配置宏接入 SEGGER RTT、串口、内存环形日志。

## 5. API 风格

命名：

- 前缀使用 `MRT_`，避免与 FreeRTOS API 混淆。
- 类型使用 `MRT_XXX`。
- 函数使用 `MRT_ModuleVerbObject` 风格，例如 `MRT_TaskCreate`。
- ISR API 统一后缀 `FromISR`。

返回值：

- 使用 `MRT_Result` 枚举表达成功、超时、参数错误、资源不足、非法上下文、对象状态错误。
- 不用 FreeRTOS 的返回宏名，避免混淆和复制。

配置：

- `mrt_config.h` 控制功能开关、最大优先级、tick 频率、栈类型、断言、trace、动态内存。

## 6. 移植层设计

端口层必须实现以下接口：

- 初始化任务栈。
- 启动第一个任务。
- 触发 PendSV/软件中断式上下文切换。
- 进入/退出临界区。
- 判断当前是否在 ISR。
- 配置 tick 中断。
- 进入/退出 tickless idle。

STM32 Cortex-M 端口：

- 使用 SysTick 产生 tick。
- 使用 PendSV 执行上下文切换。
- 使用 SVC 启动第一个任务。
- 临界区使用 PRIMASK 或 BASEPRI，按配置选择。

DSP 抽象端口：

- 提供 C 级端口接口与 mock。
- 真实 DSP 汇编保存/恢复寄存器由 `portable/dsp/<family>/` 实现。
- 先以 TI C2000 风格定义栈增长方向、对齐、寄存器保存列表和中断嵌套策略。

## 7. 测试策略

需求与耦合测试的权威追踪文件：

- `docs/verification/requirements_traceability_matrix.md`
- `docs/verification/coupling_test_matrix.md`
- `docs/verification/test_suite_plan.md`

### 7.1 Host 单元测试

覆盖：

- 链表插入、移除、排序、空表边界。
- 位图优先级选择。
- tick 溢出处理。
- 队列满/空/超时。
- 信号量计数边界。
- 互斥锁优先级继承与恢复。
- 事件组 wait-all / wait-any。
- 流缓冲环绕。
- 内存分配失败与释放合并。

### 7.2 调度仿真测试

覆盖：

- 高优先级任务抢占低优先级任务。
- 同优先级任务时间片轮转。
- 延时到期唤醒。
- ISR 唤醒更高优先级任务后请求切换。
- tick 溢出前后延时仍正确。

### 7.3 耦合测试矩阵

必须覆盖：

- 任务 + 队列 + 超时。
- ISR + 队列 + 抢占。
- 互斥锁 + 优先级继承 + 任务删除。
- 软件定时器 + 队列命令 + 定时器服务任务。
- 事件组 + 多任务等待 + 清位。
- 流缓冲 + ISR 写入 + 任务读取。
- tickless idle + 延时任务 + 定时器到期。
- 动态内存失败 + 对象创建失败路径。
- trace hook 开启后不改变内核行为。

### 7.4 嵌入式 smoke test

STM32：

- LED 心跳任务。
- UART echo 任务。
- 定时器周期回调。
- ISR 发送队列消息。

DSP：

- mock 端口 host smoke test。
- 真实 DSP 端口后补充定时器 tick 与软件中断切换示例。

## 8. 中文注释规范

每个函数必须包含：

- 函数功能。
- 输入参数。
- 返回值。
- 调用示例。
- 注意事项。
- 函数内部关键语句逐行中文注释。

注释示例结构：

```c
/**
 * @brief 创建一个任务并加入调度器管理。
 * @param name 任务名称，允许为空，仅用于调试显示。
 * @param entry 任务入口函数，不能为空。
 * @param arg 传递给任务入口函数的用户参数。
 * @param priority 任务初始优先级，数值越大优先级越高。
 * @param stack 外部提供的任务栈缓冲区。
 * @param stack_words 任务栈长度，单位为 MRT_StackType。
 * @param out_task 输出任务句柄，创建成功后写入。
 * @return MRT_RESULT_OK 表示创建成功；其他值表示失败原因。
 * @example
 * MRT_TaskHandle led_task;
 * MRT_TaskCreate("led", LedTask, NULL, 3, led_stack, 256, &led_task);
 */
```

## 10. 风险与处理

风险：

- C 版范围极大，单轮无法可靠完成全部源码、注释、手册和测试。
- 真实 DSP 端口需要明确 DSP 型号、编译器 ABI、寄存器保存规则。
- “严格按照官方使用手册模板”不能理解为逐字复制模板；只能采用相似信息结构。

处理：

- 保持目标完整，但按模块阶段推进。
- 每个模块必须先写测试，再写实现。
- 每个模块完成后更新测试矩阵与手册章节。
- DSP 先交付抽象层和 mock 测试，明确型号后补真实汇编端口。

## 11. 用户已批准的设计约束

1. 默认平台：STM32 Cortex-M4/M7 + ARM GCC/CMake + TI C2000 风格 DSP 抽象层。
2. API 前缀：`MRT_`，项目名暂定 `MyRTOS`。
3. 手册：采用原创中文结构，避免复制 FreeRTOS 手册原文。
4. 仓库：允许在当前目录初始化 Git 仓库，以便后续按阶段提交。
